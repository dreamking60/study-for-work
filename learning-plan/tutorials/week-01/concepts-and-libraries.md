# Week 01 概念与库说明

## 这周你到底在学什么
这周不是在学“做一个业务项目”，而是在学 Go 工程里最容易把人绊倒的基础：
- 参数怎么进来
- 配置怎么加载
- 路径怎么确定
- 错误怎么返回
- 测试怎么写

## 这周你会反复遇到的概念

### `module`
- 它是什么：Go 项目的模块边界
- 为什么你需要知道：导入路径和依赖管理都绕不开它

### `package`
- 它是什么：Go 的组织单位
- 为什么你需要知道：不分包的话，所有逻辑都会堆进 `main.go`

### 配置优先级
- 它是什么：多个配置来源冲突时，谁覆盖谁
- 为什么你需要知道：如果这件事不先定清，后面永远会“看起来像没生效”

## 这周最重要的标准库
- `flag`
  - 做命令行参数解析
- `os`
  - 读环境变量、找用户目录
- `filepath`
  - 安全地处理路径
- `encoding/json`
  - 处理配置文件或数据文件
- `testing`
  - 验证代码行为

不会具体怎么写时，直接看：
- [library-usage-cheatsheet.md](../library-usage-cheatsheet.md)

## 为什么这周不一上来用第三方配置库
因为你现在要学的是：
- 配置到底从哪里来
- 参数和配置怎么合并
- 错误在哪里发生

这些底层逻辑如果还没弄明白，直接套第三方配置框架只会让你更糊涂。

## 这周你经常会问的“为什么”

### 为什么先补 `--config`
因为这是让 CLI 真正具备工程工具价值的第一步。

### 为什么先定数据路径，而不是先做 task 子命令
因为后续所有本地数据操作都依赖路径规范，路径不定，后面都要返工。

### 为什么这周写这么多测试
因为你现在在建立基础层。基础层不稳，后面每一周都会被拖慢。
