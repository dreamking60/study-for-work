# Week 01 Day 6：把 README 写成你下周还能看懂的样子

## 今天你要完成什么
今天不追求新功能，专门收口文档。

你现在最需要的不是“再加一个命令”，而是：
- 把现在这份工具讲明白
- 把运行方式写明白
- 把边界写明白

## 这份 README 至少要有 5 段

### 1. 这是什么
一句话说清：
- 这是后续项目的工程 CLI，不是最终业务服务

### 2. 现在能做什么
例如：
- 运行主命令
- 读取配置
- 输出摘要

### 3. 现在还不能做什么
例如：
- 还没有完整数据播种
- 还没有回放命令
- 还没有真正的任务存储体系

### 4. 怎么运行
写最小命令：
```bash
go test ./...
go run ./cmd/app run
go run ./cmd/app run --config ./sample.json
```

### 5. 它后面会服务哪些项目
至少要写：
- `edge-gateway`
- `room-orchestrator`

## 为什么今天必须写“现在还不能做什么”
因为这是教程，不是项目宣传页。

如果你不写边界，下周你自己回来都容易误判：
- 以为这里已经做了完整存储
- 以为这里已经是最终项目

## 今天完成后的标准
- README 能让一周后的你自己快速进入状态
- README 里有运行命令
- README 里有边界说明

## 今天会用到的库和最小代码

### Markdown 里的命令块应该这样写
````md
```bash
go test ./...
go run ./cmd/app run --config ./sample.json
```
````

### 为什么文档里也要写代码块
因为你希望这套教程离线可用。
如果 README 里连最小命令都没有，后面每次都得回头翻聊天记录。

## 根据你之前报告补充的真实坑
- 你之前每一天其实已经积累了很多有价值的验证命令，这些不要只留在 report 里，应该回收进 README 和教程正文
