# Week 01 Day 7：写周报告，把这周真正做成一个闭环

## 今天你要完成什么
今天不是再加一层功能，而是把这一周收成一个清晰闭环。

## 这份周报告必须写 4 件事

### 1. 保留了哪些旧成果
例如：
- 已有命令
- 已有测试
- 已有配置结构

### 2. 本周新增了哪些真实能力
例如：
- `--config`
- 数据路径规则
- 更清晰的日志和错误输出

### 3. 它将如何服务后续项目
分别写：
- 它如何服务 `edge-gateway`
- 它如何服务 `room-orchestrator`

### 4. 下周开始前你还差什么
例如：
- 还没有真实播种命令
- 还没有真正的数据读写

## 今天你要跑的最终检查命令
```bash
go test ./...
go run ./cmd/app run
go run ./cmd/app run --config ./sample.json
go run ./cmd/app task-summary
```

## 这份报告为什么很重要
因为后面教程越来越大，如果你每周不收口，会很快出现这种情况：
- 做了很多，但讲不清
- 写了很多，但不知道哪些已经落地

这份周报告就是为了防止这种事。

## 今天完成后的标准
- 你能用一段话讲清本周成果
- 你能说明它和下周的关系
- 你已经准备好进入 `edge-gateway`

## 今天会用到的库和最小代码

### 报告里建议贴的命令
```bash
go test ./...
go run ./cmd/app run
go run ./cmd/app run --config ./sample.json
```

### 为什么报告里要贴命令
因为“我做过了”和“我能复现给别人看”不是一回事。

离线教程最怕只写结论，不写复现方式。

## 根据你之前报告补充的真实坑
- 你之前对 coverage 的理解其实已经很好了，所以这周总结里不要只写“测试过了”，要写“哪些地方高价值、哪些地方暂时没必要追 100%”
- 你已经把单入口 CLI 改成了子命令分发，这件事应该出现在本周总结里，不能被埋掉
