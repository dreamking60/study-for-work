# Week 09 教程：联调、交付和 CI 收口

## 本周目标
- 打通一条跨项目链路
- 补基础观测
- 加最小自动化交付

## 本周产物最低要求
- 一条可演示链路
- 一份联调清单
- 一份构建或发布脚本

## 第 1 天：列联调清单
写清楚：
- 哪些服务参与
- 启动顺序
- 输入输出

建议直接写成表格或 checklist，而不是自然语言散文。

## 第 2 天：打通最小链路
目标：
- `edge-gateway` 接到请求
- `room-orchestrator` 接手状态变化

完成标准：
- 你能录一段终端操作或至少保存一组执行命令

## 第 3 天：加基础指标
至少有：
- QPS 或请求数
- 延迟
- 错误数

没有正式监控系统时，可以先用日志统计替代。

## 第 4 天：整理日志和看板
就算没有完整 Grafana，也要有一份汇总方式。

## 第 5 天：补 Dockerfile 和构建脚本
至少自动化掉这些：
- 构建
- 测试
- 打包

建议优先产出：
- `Makefile`
或者
- `scripts/build.sh`

## 第 6 天：做一次发布或回滚演练
你要知道：
- 怎么发布
- 发布失败怎么退

如果这周还没有真实发布环境，就做本地“构建失败如何回滚到上一个二进制”演练。

## 第 7 天：写交付报告
说明：
- 这组项目现在如何演示
- 哪条链路已经闭环
- 还差哪些生产级能力

## 本周最终自检命令
```bash
go test ./...
```
