# Week 03 概念与库说明

## 这周你到底在学什么
如果说 Week 02 解决的是“消息怎么进来、房间怎么建起来”，那么 Week 03 解决的是：
- 谁能发消息
- 哪些消息可以进业务逻辑
- 服务内部的状态应该怎么存

也就是说，这周开始从“骨架”进入“规则”。

## 这周最重要的概念

### 鉴权
- 它是什么：判断当前请求或消息是不是来自合法身份
- 为什么现在就要加：如果消息入口没有边界，后面所有房间逻辑都不可信

### Session Store
- 它是什么：保存连接、用户、房间等上下文的地方
- 为什么现在要抽出来：如果 handler 直接操作裸 map，后面很难维护

### Error Model
- 它是什么：一组固定、可预测的错误分类
- 为什么重要：如果错误全靠字符串拼接，后面联调和排障会非常痛苦

### Heartbeat
- 它是什么：连接告诉服务“我还活着”的机制
- 为什么会在这周出现：你已经有连接和房间了，下一步自然就是让连接状态真实可靠

## 这周会用到的 Go 能力
- `time`
  - 用来表示 session 过期时间、心跳时间
- `errors`
  - 用来定义和判断错误类型
- `sync`
  - 如果你把 session store / room store 抽出来，就会马上遇到并发读写问题

## 为什么这周还先不做 JWT
因为你当前最重要的是先学会“鉴权放在哪里、消息在什么时候被拦住”。

如果你现在直接上完整 JWT：
- 你可能学会了 token 字符串怎么长
- 但不一定学会了鉴权边界怎么设计

所以这周用最小版鉴权更合理。

## 为什么这周要抽出 store
因为从这周开始，逻辑会越来越多：
- join
- message
- heartbeat
- leave
- 断开清理

如果你还让 handler 直接操作共享状态，Week 04 做稳定性时会非常难收口。
