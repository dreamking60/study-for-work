# Week 02 概念与库说明

## 这周你到底在学什么
这周你开始从“工程工具”转向“实时服务”。

你这周最重要的不是做出一个多厉害的网关，而是先学会这几件事：
- 消息协议怎么定义
- 路由怎么拆
- 房间成员怎么管理
- 为什么要先做内存版

## 这周会反复遇到的概念

### 消息协议
- 它是什么：客户端和服务端都能理解的数据格式
- 为什么你现在先用 JSON：看得见、容易 debug、对初学者友好

### Session
- 它是什么：一条连接对应的上下文信息
- 为什么重要：你后面会用它串起用户、房间、连接状态

### Room
- 它是什么：房间内成员和消息流转的边界
- 为什么重要：如果没有这层边界，广播和成员管理会非常混乱

### Router
- 它是什么：根据消息类型把消息分发到不同处理逻辑的入口
- 为什么重要：后面要加鉴权、心跳、错误模型，都依赖你先有统一入口

## 这周最重要的标准库
- `encoding/json`
  - 解消息、验消息
- `sync`
  - 保护房间成员等共享状态
- `time`
  - 后面做心跳和超时会马上用到
- `testing`
  - 保证协议解析、路由和房间逻辑不乱

## 为什么现在还不急着上这些东西

### 为什么先不用 Redis
因为你现在还在确认房间模型和消息流向。内存版没讲清楚，上 Redis 只会把问题藏起来。

### 为什么先不做 JWT
因为你现在先要学“路由和房间模型”，不是先做完整安全体系。

### 为什么先不做 K8s
因为实时服务本身的行为还没讲清楚，先谈部署没有意义。

## 这周你经常会问的“为什么”

### 为什么 `join` 要先做
因为它决定房间成员表能不能成立。

### 为什么 `chat` 要在 `join` 后面做
因为广播逻辑依赖成员集合。

### 为什么要先做断开清理
因为没有清理，你的房间状态很快就会失真。
