# Week 04 Day 4：把并发风险找出来，不要等 bug 自己长出来

## 今天你要完成什么
今天先不急着全修并发问题，而是先把风险点找全。

## 你今天重点看哪些地方
- 房间成员 map
- session store
- 广播时的遍历
- disconnect 和 cleanup 的交叉路径

## 为什么今天先做风险清单
因为并发问题很少是“看一眼就修完”的。

你先找清楚哪里会：
- 同时读写
- 遍历时删除
- 多个 goroutine 改同一对象

后面修起来才不会盲目。

## 今天完成后的标准
- 你已经列出风险清单
- 你知道明天最优先修哪个点

## 今天会用到的库和最小代码

### 共享 map 最危险的典型写法
```go
room.Members[sess.ConnID] = sess
delete(room.Members, connID)
```

### 为什么今天只列风险，不先乱加锁
因为你要先知道“谁在同时改这块数据”，再决定锁放在哪一层。
