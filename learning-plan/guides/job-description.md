# 目标岗位整理

这份文档的用途不是继续堆原始 JD，而是把你真正要证明的能力整理出来，作为后续项目立项依据。

## 岗位 A：游戏服务器开发

### 关键词
- 高并发、高在线、低延迟、稳定运行。
- 游戏玩法实现、功能开发、性能优化、工具开发。
- 网络编程、数据库、分布式服务。

### 面试官最可能关注什么
- 你是否真的做过长连接 / 实时消息链路，而不是只写普通 CRUD。
- 你是否理解高并发下的连接管理、消息路由、限流、异常恢复。
- 你是否能把“玩法需求”拆成房间、会话、状态流转等服务模块。
- 你是否能拿出压测、日志、监控或优化案例，而不是只说“性能很好”。

### 必须覆盖的能力
- Go 工程化与测试。
- TCP/WebSocket/gRPC 其中至少一种实时通信方式。
- 会话管理、鉴权、房间/匹配/任务状态流转。
- Redis / MySQL 等常见存储的基本使用与优化意识。
- 并发安全、错误处理、性能分析。

### 可以作为加分项的能力
- 自动化工具、AI 辅助开发、运营支撑工具。
- 数据回放、压测脚本、线上问题定位能力。

## 岗位 B：云平台 / DevOps / 基础设施

### 关键词
- 多租户、多集群、资源管理。
- Kubernetes / containerd / Linux。
- CI/CD、平台产品化、智能化运维。

### 面试官最可能关注什么
- 你是否真的理解控制面、资源对象、Reconcile、部署流程，而不是停留在会用 `kubectl`。
- 你是否做过和发布、监控、集群管理相关的自动化工具或平台能力。
- 你是否能在 Linux 环境下定位问题、读日志、看进程、分析资源占用。
- 你是否能讲清 Go 服务如何部署、观测、回滚、扩容。

### 必须覆盖的能力
- Go 服务工程化、配置管理、日志与错误处理。
- 容器和 Kubernetes 基础对象模型。
- 调度 / 编排 / 控制器思想。
- CI/CD 和可观测性基础。
- Linux 基础排障。

### 可以作为加分项的能力
- Operator / Controller 开发。
- 多环境发布、自动扩缩容、智能运维。
- 结合 AI 或自动化提升运维效率。

## 两类岗位的交集
- Go 代码质量和测试。
- 高并发 / 高可用意识。
- 工程化、配置、日志、错误处理、可观测性。
- 面向真实场景的模块拆分能力。

## 由岗位反推本轮项目立项
- 不能只做一个“教学型 CLI 小作业”，因为它覆盖不了网络编程、编排、K8s。
- 也不能只做一个“纯 K8s demo”，因为它覆盖不了游戏服务器岗关注的实时链路。
- 最合适的是一组连续项目：
  - 一个实时接入网关，证明网络与高并发。
  - 一个房间 / 任务编排服务，证明状态机与分布式可靠性。
  - 一个部署控制面或 Operator，证明平台与自动化能力。
- 已完成的 CLI 工作保留，但定位降级为工程基础设施和运维工具。
