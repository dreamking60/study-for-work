# Go 后端求职学习计划（项目驱动版）

## 先看什么
1. 先读 `guides/job-description.md`，确认目标岗位真正要你证明的能力。
2. 再读 `projects/project-overview.md`，确认本轮采用的项目主线。
3. 直接从 `tutorials/README.md` 开始，`tutorials/` 现在是正文。
4. 旧的 `weekly/` 和 `week01-cli/` 教程目录已经移除，不再作为阅读路径。
5. 每周结束按 `guides/weekly-checklist.md` 和 `guides/execution-standard.md` 产出交付物。

## 目录说明
- `guides/`: 岗位要求整理、项目候选池、参考仓库使用方式、执行规范。
- `projects/`: 最终立项结果、项目拆分、简历话术。
- `tutorials/`: 直接照着做的实操教程，基于参考仓库和官方文档整理。
- `report/`: 已完成的日更记录，作为阶段成果存档，不删除。
- `templates/`: PRD/HLD/压测报告模板。

## 当前项目主线
- 项目 0：`opsctl` 工程 CLI
  作用：保留你已经完成的 `week01-cli` 代码，把它升级成后续项目复用的配置、调试、数据导入导出和运维脚手架。
- 项目 1：实时接入网关 `edge-gateway`
  作用：承接游戏服务器岗的网络编程、高并发、长连接、鉴权、可观测性。
- 项目 2：房间与任务编排服务 `room-orchestrator`
  作用：承接状态机、幂等、重试、补偿、分布式调度。
- 项目 3：部署控制面 / K8s Operator `cluster-operator`
  作用：承接云平台岗的 Kubernetes、资源管理、发布与自动化运维。

## 这版和旧版的区别
- 不再把学习计划写成概念课表，而是每周都服务于一个真实项目阶段。
- 不再把 `week01-cli` 当作孤立练习，而是把现有成果升级成全局工具链。
- 每个项目都明确对应岗位能力、参考仓库、可交付物和简历讲法。

## 核心目标
- 用一套连续项目覆盖两类岗位：游戏服务器开发岗 + 云平台 / DevOps / 基础设施岗。
- 保留你已经完成的 Day1-Day7 工作，但把后续学习重心切到更贴近岗位的项目实现。
- 每个阶段都必须落到代码、测试、设计文档、压测或演练记录，而不是只写说明。
